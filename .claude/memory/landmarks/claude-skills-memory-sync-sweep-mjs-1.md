- Role: deterministic actuator for /memory-sync Step 0 AND for /commit Step 2.7. Five modes via `--mode {auto-close, prose-scan, stale-sweep, stamp-closure, backlog-decay}` + `--memory-dir`. auto-close deletes blocks carrying valid `resolved-at:` (pending-questions) or `superseded-at:` (the other seven canonical categories) and flags malformed dates + per-file invariant violations. prose-scan surfaces entries whose body matches R1/R2/R3 (Resolution path/Superseded by/Resolved by, anchored, case-insensitive) and applies stdin replies (y deletes, n keeps, skip defers). stale-sweep re-derives the stale set with the same predicate as `memory_session_start.mjs:1` and applies stdin replies (re-verify / delete / mark-closed / skip). stamp-closure (non-interactive) takes `--backlog-keys <csv>` and writes `status: picked-up` + `superseded-at: <today>` to each named backlog.md entry; invoked by /commit Step 2.7 (pre-stage, so the stamp rides the same commit) when workflow.json → source_backlog_keys is populated; report shape `{stamped, missing, already_closed}`. backlog-decay surfaces backlog entries older than `--threshold-days` (default 90) and applies stdin replies (keep / drop / picked-up / skip). Emits JSON action report on stdout.
- Caveat: the stale predicate is no longer duplicated. Since 8201af6 this module imports `CANONICAL`, `STALE_EXEMPT`, `SUPERSESSION_DRIVEN` and `closureFieldFor` from `.claude/skills/memory-index/categories.mjs` — the same registry `memory_session_start.mjs:1` reads — and `tests/sweep-staleness-parity.test.mjs` pins the two predicates equal entry-by-entry over the live store. Before that fix the local copy lacked the `SUPERSESSION_DRIVEN` guard and omitted `constraints`: at 1b2b0c7 it called 287 entries stale where the hook called 248. Spec design diagram says 90 days; the 30-day choice matches the test plan AC-003 row and the index header label `stale (>=30 commits old)`. The helper trusts argv strings reaching `git rev-list` (e.g., the verified-at value as `<stamp>..HEAD`); a malicious memory file could feed a `--exec`-style argv flag — low risk because filesystem write to `.claude/memory/` already implies broader compromise. See `docs/archive/2026-05-13/memory-lifecycle-closure/security.md` LOW finding. stamp-closure has its own LOW finding (CWE-22 path traversal via slug; CWE-78 shell quoting of backlog-keys CSV) — see `docs/archive/2026-05-17/workflow-loop-closing-hygiene/security.md`; mitigations are non-blocking carve-outs for a future hardening workflow.
