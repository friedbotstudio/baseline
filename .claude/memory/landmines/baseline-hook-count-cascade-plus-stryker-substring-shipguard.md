- Trap: adding a baseline HOOK (e.g. `gitignore_leak_guard` in gitignore-setup, 23→24) is a wider cascade than a skill add. Beyond the skill-add surfaces ([[baseline-skill-count-cascade]]), a hook add must also: add the name to `EXPECTED_HOOKS`; wire it in BOTH settings files' Bash matcher; bump `19 write/run-boundary guards`-style category sub-counts in seed §4.1/headline/tree (not just the total); and fix FOUR test files that hard-code the old hook count as integer literals AND in test NAMES (`exactly_23`). `.claude/CONSTITUTION.md` Appendix A hook count is NOT audited (no count regex over the annex) so it silently drifts — it read a stale `22` while disk was 23; re-verify and correct it on every hook change. The site `_data/baseline.cjs` block in `derive-counts.test.mjs` carries its own `data.hooks.total`/`data.skills.total` literals separate from the deriver assertion.

Keep tool-specific scratch patterns (`.stryker-tmp/`, repo-only build dirs) OUT of the shipped generic must-ignore set; they belong in the dev repo's own `.gitignore`, not the consumer default.
