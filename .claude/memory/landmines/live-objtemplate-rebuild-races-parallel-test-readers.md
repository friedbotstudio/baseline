- Path: `tests/build-template.test.mjs` (and other build-exercisers) vs any test that reads `obj/template/**`; helper `tests/helpers/clone-and-build.mjs`.
- Trap: `build-template.test.mjs` runs `scripts/build-template.sh` against the LIVE tree (PKG_ROOT=repo root), which `rm -rf`s + rebuilds `obj/template/` (including `manifest.json`). Under default-parallel `node --test tests/*.test.mjs`, any OTHER test that reads the live `obj/template/` races that rebuild and fails intermittently: ENOENT on `manifest.json`, a half-written manifest, a transient scan finding, or a build-mutex timeout. Observed: a fresh `whatsnew-counts.test.mjs` that read the live manifest produced 4 different failure shapes across 3 consecutive full runs (ENOENT -> mutex-timeout -> scan), every one GREEN in isolation. The flakes are NOT real test failures.
- Mitigation: (1) a test that needs the BUILT tree must build its OWN isolated copy via `tests/helpers/clone-and-build.mjs` (`cloneAndBuild(label)` rsyncs the repo to a tmpdir, builds there, returns the path) and read from that path, NOT the live `obj/template/`. (2) Better still, assert the SOURCE of truth (e.g. skill frontmatter `owner: baseline` + dir presence) instead of the built manifest when possible — rebuild-free and contention-free. (3) For a deterministic binding verdict at `/integrate`, run the suite serially: `node --test --test-concurrency=1 tests/*.test.mjs` avoids the shared-live-tree race entirely. RE-CONFIRMED 2026-06-03 (drift-check-working-tree-diff workflow): `npm test` (= `node --test tests/*.test.mjs`, NO concurrency pin → parallel) surfaced `thread-shelving-governance.test.mjs` FAIL (`audit overall FAIL fails=1`) that passed in isolation and under the serial command; the serial run was clean (750 pass / 0 fail).
- Mitigation status (UPDATED 2026-06-05, reduce-test-suite-runtime): now STRUCTURALLY enforced for the default tier. Root cause confirmed to be the WRITERS — `npm pack` (via `prepack` → `build-template.sh`) rebuilding the live `obj/template` while sibling tests read it. Fix: the heavy `publish-check` npm-pack/install cases + the one live-tree-writing supply-chain case are gated behind `PUBLISH_TESTS=1`; the always-on packaging smoke uses `npm pack --dry-run --ignore-scripts` (skips prepack → no rebuild). New meta-test `tests/no-live-objtemplate-reads.test.mjs` FAILs if any default-tier test executes a build/`npm pack` against the live tree without isolation or a gate (regression guard). Result: default-parallel `node --test tests/*.test.mjs` is now deterministic — 8/8 consecutive green (was 2/3 red). The serial `--test-concurrency=1` run is KEPT as a documented fallback (not retired) per spec Decision. Speed remains unaddressed (see backlog `reduce-test-suite-wall-clock-blocked-on-global-build-mutex`).
- RE-CONFIRMED 2026-08-04 (tracking-annotations), with a NEW trigger the 2026-06-05 structural fix does not cover: **two full-suite runs of my own, overlapping.** A backgrounded `--test-reporter=spec` run was still executing when a `--test-reporter=tap` run started; the TAP run reported `# fail 3` with no `not ok` line anywhere in its output, while the spec run finished `fail 0`. A clean serial re-run gave 2172 / 2157 pass / 0 fail. The 2026-06-05 fix removed the *writer* (npm pack rebuilding the live tree); it cannot stop a second reader you launched yourself. The counts even reconcile — 2154+3 = 2157 — which makes the phantom failures look like a real regression rather than contention.
- **Practical rule for the operator, not the suite:** never start a second full-suite run while one is in flight, and treat any `# fail N` with no matching `not ok` line as contention until a serial re-run says otherwise. A backgrounded run that takes 56 minutes instead of 3 is the tell.
- **WIDENED 2026-08-06 (audit-flake-writer-isolation): the trap is TWO live trees, and the 2026-06-05 guard missed three shapes.** The audit reads `obj/template/.claude/manifest.json` (`checks/context.mjs:37`) AND five rendered pages under `obj/site` (`checks/docsite-drift.mjs`). `docsite-drift` landed AFTER the guard was written, so `npm run build:site` — explicitly excluded by the guard's own comment as "obj/site (not obj/template)" — silently became a racing writer. Measured on the live tree: an `mtime` probe across one `npm test` run showed ~45 files rewritten under `obj/template/` + `obj/site/`; after the fix, zero.
- The three guard blind spots, all now closed in `tests/no-live-objtemplate-reads.test.mjs`: (1) **variable indirection** — `execsBuildSh` required the literal `build-template.sh` INSIDE the exec-call parens, so `const BUILD_SH = path.join(...); spawnSync('bash', [BUILD_SH, '--manifest-only'])` (tests/manifest-refresh.test.mjs) was never reported; (2) **the stale `build:site` exclusion**; (3) **helper-mediated writers** — the scan walked only `tests/*.test.mjs`, and `tests/helpers/site-build.mjs` was building the live site from NINE test processes, invisible to it. When you widen an oracle, widen its *scan surface* too: moving the offending call behind a helper is the cheapest way to make a guard lie.
- **Diagnosis lesson, worth more than the fix:** the flake did NOT reproduce in 6 full suite runs, ~2500 concurrent audit invocations, or a targeted race against a live site build. Do not wait for a repro to remove confirmed shared mutable state. The evidence path that actually pays is `tests/helpers/audit-repo.mjs` (`runRepoAudit`), which writes the audit's full stdout+stderr to `.claude/state/logs/audit-failure-<label>.log` before throwing — bare `execFileSync` loses it to reporter truncation, which is why two prior occurrences were unattributable. It earned its keep the same hour it landed, naming a manifest hash-mismatch instantly.
- **`--manifest-only` is an incremental refresh, not a from-scratch build.** It skips Stages 0a/0b, including the `mkdir -p "$TEMPLATE_DIR/docs/init"`, so it fails in a fresh clone with `cp: .../obj/template/docs/init/seed.md: No such file or directory`. A test isolating it must `cloneAndBuild` first, then run the refresh over the result.
- **Cost of the fix, so nobody re-litigates it:** default suite wall-clock 89s → 141s, almost entirely `manifest-refresh` now doing a real clone+build. Related: [[full-suite-intermittently-fails-three-audit-spawning-tests]], [[baseline-skill-edit-needs-manifest-rebuild]].
- **The guard also FALSE-POSITIVES, and the fix is never to fake isolation (2026-08-12, consumer-install-defects).** `no-live-objtemplate-reads.test.mjs` matches on file TEXT. It strips comments before scanning but NOT string literals, so any test that both calls an exec function and mentions the build command in a user-facing string is reported as an un-isolated live-obj writer. Two new test files tripped it purely through their skip-reason wording (`'… run `npm run build` first'`) while execing only a `node -e` probe and writing nothing. The correct fix is to reword the message; a sibling file escaped only incidentally because its `mkdtempSync` for a temp report root happens to match the ISOLATION regex. **Do not add a decorative `mkdtemp` or a `PUBLISH_TESTS` gate to quiet the pattern** — that buys silence from the one guard that would otherwise name the next real writer. Every prior widening of this guard closed a false NEGATIVE; this is its first recorded false POSITIVE, and the two failure directions want opposite reflexes.
