- Path: `.claude/skills/audit-baseline/derive-counts.mjs` (`SKILL_CATEGORIES` map + `SPELLED`/`NUM_WORDS`) + `.claude/skills/audit-baseline/audit.mjs` (word→num map ~line 139, skills-count regex ~227, `NUM_GROUP` ~722) + `CLAUDE.md` + byte-equal mirror `src/CLAUDE.template.md` + `docs/init/seed.md` + mirror `src/seed.template.md` + `README.md` + `.claude/CONSTITUTION.md` (Appendix A count line + Appendix B skill index) + governance-count test literals (`tests/derive-counts.test.mjs`, `tests/whatsnew-counts.test.mjs`).
- Trap: adding or removing a baseline-owned skill is an **N→N+1 count cascade**, not a one-file edit. `audit-baseline` cross-checks the on-disk `owner: baseline` count against EVERY prose surface that states a skill count, the `SKILL_CATEGORIES` category sum, AND the spelled-out word forms. Miss any one and the audit FAILs with one of: `skills count (seed vs baseline)`, `skills byCategory sum != total`, `docs/init/seed.md count claims`, or a hash-drift row. Two non-obvious gotchas surfaced live (standup-skill, 2026-06-08): (1) the skills-count regex matches the FIRST `\d+|<word> skills` in seed.md — seed.md:14 uses the WORD form ("forty skills"), so the digit edits elsewhere don't satisfy it; you must bump the word form too AND add the new word to `NUM_WORDS` (e.g. `41: 'forty-one'`), the audit word→num map (`'forty-one': 41`), and BOTH number regexes (the `forty-one|forty` ordering matters). (2) `numToWord(N+1)` THROWS on an unmapped value, crashing the audit rather than cleanly FAILing — add the spelled form first.
- Mitigation: when adding/removing a baseline skill, sweep all surfaces in one change-set: bump the category in `SKILL_CATEGORIES` (sum must equal the new total), add the spelled word to `NUM_WORDS` + audit word-map + both regexes, edit every `N skills`/`Skills (N)`/`forty skills` surface (digit AND word) in CLAUDE.md+mirror, seed.md+mirror, README, CONSTITUTION (count line + Appendix B list row), update the two governance-count test literals, then `bash scripts/build-template.sh` to restamp the manifest, and finally `node .claude/skills/audit-baseline/audit.mjs` until exit 0. - **NEW SUB-TRIGGER — adding a new skill CATEGORY (2026-06-23, `sprint-completeness-oracle` slice A, added 2 skills `sprint-plan`+`sprint-oracle` as a brand-new `sprint` category 43→45):** when the 2 new skills form a NEW `SKILL_CATEGORIES` key (not a +N to an existing category), the **category COUNT** also bumps (13→14 categories). So this class is caught at **`/integrate`** (full suite), NOT at audit — do not trust an audit-clean tree as cascade-complete when a new category was added. The fix is one `SPELLED` entry.
